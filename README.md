# Object Project — C++ 植物大战僵尸

一个由个人独立设计与开发的 C++ 塔防游戏项目。本项目参考《植物大战僵尸》的核心玩法，目标不只是满足课程实验的最低要求，而是完成一个结构清晰、玩法丰富、可以在 Visual Studio Code 中构建和运行的面向对象游戏。

> 当前状态：M3 课程最低要求已完成并通过人工窗口交互验收，正在开发 M4 丰富玩法。本文中的功能分为“课程最低要求”和“扩展目标”，只有在完成并通过测试后才会标记为已实现。

## 一、项目目标

玩家通过收集阳光、选择植物并将其种植在草坪网格中，抵挡从右侧不断出现的僵尸。僵尸突破草坪左侧防线时游戏失败；所有波次结束且场上僵尸被消灭时游戏胜利。

项目重点：

- 使用 C++ 完成全部核心代码；
- 运用封装、继承、多态和组合等面向对象技术；
- 至少实现 5 种植物和 3 种僵尸，并提供完整图鉴介绍；
- 在最低要求之上增加更丰富的植物、僵尸、关卡和交互系统；
- 使用清晰、可扩展的类结构，避免将全部逻辑堆放在单个文件中；
- 支持在 Windows 与 Visual Studio Code 环境中构建、运行和调试；
- 为核心规则编写测试，保证战斗数值和胜负逻辑可靠。

## 二、开发说明

- 开发者：个人独立开发
- 开发语言：C++17 或更高版本
- 图形与音频：SFML
- 构建工具：CMake
- 开发环境：Visual Studio Code
- 目标平台：Windows 10/11
- 代码仓库：<https://github.com/yeyeye-88/Object_Project>

**CMake** 是用于统一管理 C++ 编译过程的工具，它负责组织源文件、第三方库和生成可执行程序，使项目不依赖某一台电脑上的固定路径。

**SFML** 是用于创建游戏窗口、绘制图片、播放声音和处理键盘鼠标输入的 C++ 多媒体库。

## 四、计划中的丰富玩法

下列内容是项目的完整开发目标，不代表当前已经实现。开发时会按照里程碑逐步完成，并根据时间和质量调整优先级。

### 4.1 植物阵营

计划优先实现 10 种植物，覆盖资源、单体攻击、范围攻击、控制、防御和一次性爆发等不同定位。

| 植物 | 定位 | 计划能力 |
| --- | --- | --- |
| 向日葵 | 资源 | 周期性生产阳光，是经济体系的核心 |
| 豌豆射手 | 基础输出 | 攻击同一行最靠前的僵尸 |
| 双发射手 | 强力输出 | 连续发射两枚豌豆，输出更高但费用更高 |
| 寒冰射手 | 输出/控制 | 子弹造成伤害并降低僵尸移动与攻击速度 |
| 坚果墙 | 防御 | 高生命值阻挡僵尸，并随受伤程度改变外观 |
| 高坚果 | 强力防御 | 更高生命值，可以阻挡部分跨越类僵尸 |
| 土豆地雷 | 延时爆发 | 种下后需要准备时间，触发时造成高额单体伤害 |
| 樱桃炸弹 | 范围爆发 | 延迟后对周围区域造成大量伤害 |
| 火炬树桩 | 增益 | 将经过的普通豌豆强化为火焰豌豆 |
| 三线射手 | 多行输出 | 同时攻击自身行及相邻两行 |

扩展候选：食人花、窝瓜、磁力菇、南瓜头和地刺。候选内容只有在核心版本稳定后才进入实现阶段。

### 4.2 僵尸阵营

计划优先实现 6 种僵尸，使不同关卡具有明确的阵容变化和应对策略。

| 僵尸 | 定位 | 计划能力 |
| --- | --- | --- |
| 普通僵尸 | 基础单位 | 标准生命值、速度和攻击力 |
| 路障僵尸 | 轻甲单位 | 具有额外护甲，护甲损坏后变为普通状态 |
| 铁桶僵尸 | 重甲单位 | 高额护甲，需要持续火力处理 |
| 旗帜僵尸 | 波次标志 | 在大型波次出现，用于强化演出和提示压力 |
| 撑杆僵尸 | 突进单位 | 第一次遇到植物时越过目标，之后恢复普通移动 |
| 报纸僵尸 | 狂暴单位 | 报纸被破坏后提高移动速度和攻击速度 |

扩展候选：铁栅门僵尸、橄榄球僵尸、舞王僵尸和伴舞僵尸。

## 五、面向对象设计

### 5.1 设计原则

- **封装**：生命值、位置、冷却等内部状态由类自身维护，通过明确接口访问；
- **继承**：具体植物继承 `Plant`，具体僵尸继承 `Zombie`；
- **多态**：通过虚函数让不同植物执行不同能力，让不同僵尸执行不同移动或攻击行为；
- **组合**：游戏对象组合动画、碰撞体、状态效果等组件，减少重复代码；
- **单一职责**：渲染、输入、战斗、资源、波次、存档分别由不同模块负责；
- **开闭原则**：增加新植物或僵尸时，尽量通过新增类型和配置完成，而不是大量修改旧代码。

## 八、构建与运行

工程使用 CMake Presets 统一管理配置、构建和测试。首次配置会从 SFML 官方仓库下载固定的 3.1.0 版本，因此需要连接网络；后续在依赖未变化时可以直接使用本地构建目录。

### 环境要求

- Visual Studio Code；
- VS Code 扩展：C/C++、CMake Tools；
- CMake 3.28 或更高版本（已使用 4.4.4 验证）；
- 支持 C++17 的编译器（已使用 MinGW GCC 16.1.0 验证）；
- Git。

### 配置、构建与测试

```powershell
git clone https://github.com/yeyeye-88/Object_Project.git
cd Object_Project
cmake --preset mingw-debug
cmake --build --preset mingw-debug --parallel 4
ctest --preset mingw-debug
```

### 运行

```powershell
.\build\debug\bin\pvz_game.exe
```

也可以在 VS Code 中选择 `MinGW Debug` 预设，使用 `Ctrl+Shift+B` 构建，然后按 `F5` 启动调试。

当前 M4 开发版本会读取 `assets/config/window_title.txt`，打开一个 960×600 的游戏窗口：

- 程序从主菜单启动，可以进入关卡选择或直接查看图鉴；
- 关卡选择提供教学关卡、三波花园防守和四波夜间压力关卡，各自具有不同初始阳光、可用植物和僵尸生成计划；
- 顶部提供向日葵、豌豆射手、坚果墙、双发射手、三线射手、寒冰射手、高坚果、土豆地雷、樱桃炸弹和火炬树桩共 10 张卡片；点击卡片后再点击草坪空格完成种植；
- 鼠标悬停时显示种植预览，红色格子表示当前位置不可种植；
- 点击铲子后再点击已有植物，可以将植物铲除；
- 点击从天空掉落的阳光可以增加资源；
- 按 `Esc` 或点击右上角按钮暂停/继续；
- 按 `R`，或在暂停界面点击重开按钮，重新开始当前游戏。
- 向日葵会周期性生产阳光，豌豆射手会攻击同行僵尸，坚果墙能够承受更多伤害；
- 寒冰射手会用寒冰豌豆降低僵尸移动和攻击速度，高坚果拥有更高生命值并能够阻止撑杆僵尸越过；
- 土豆地雷准备完成后消灭一个靠近的僵尸，樱桃炸弹短暂延迟后攻击三行范围，火炬树桩会把经过的普通豌豆强化为双倍伤害的火焰豌豆；
- 普通、路障、铁桶、旗帜、撑杆和报纸僵尸会按照所选关卡的生成计划出现；
- 撑杆僵尸首次遇到普通植物时会越过目标，报纸僵尸的报纸破坏后会提高移动和攻击速度；
- 路障、铁桶和报纸优先损失护甲，护甲耗尽后才会损失本体生命值；
- 顶部波次面板显示当前波次，最终波会变为红色；
- 点击右上方书本按钮进入图鉴，可切换植物/僵尸分类并查看能力、数值和建议；
- 暂停或结算界面可以返回关卡选择；
- 每行割草机只能触发一次，清除最后一只僵尸后胜利，防线再次被突破后失败。

## 九、质量与验收标准

### 功能验收

- 所有植物能力与图鉴描述一致；
- 所有僵尸能力与图鉴描述一致；
- 阳光不足、卡片冷却、格子被占用时不能错误种植；
- 僵尸、植物和子弹死亡后不再参与碰撞；
- 最后一波生成结束不等于立即胜利，必须清除场上全部僵尸；
- 割草机只能触发一次，失去割草机后被突破才判定失败；
- 暂停时游戏计时、移动和攻击保持一致暂停。

### 工程验收

- 编译时无错误，并尽量消除警告；
- 不依赖开发者电脑上的绝对路径；
- 核心规则与界面绘制适当分离；
- 不使用裸指针随意管理对象生命周期，优先使用 RAII 和智能指针；
- 核心规则具有自动化测试；
- 提交记录能够反映各阶段开发过程。

**RAII** 是让 C++ 对象在生命周期结束时自动释放资源的管理方式，可以减少内存泄漏和重复释放问题。
